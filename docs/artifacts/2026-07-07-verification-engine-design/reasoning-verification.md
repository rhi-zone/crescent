# Reasoning verification — 2026-07-07

Purpose: three parallel verification passes over the [UNVERIFIED] orchestrator framings in ./discussion-log.md, checking each memory-stated claim against primary/authoritative CS sources. Verdicts: CONFIRMED / CORRECTED / OVERSTATED / UNSUPPORTED. Headline: no claim was fabricated, but several central framings were overstated or imprecise — most consequentially the "typecheckers are polynomial" and "typecheckers vs SMT = one family separated by disjunction handling" framings. Details below. Where a source could not be fetched, the verdict is marked as resting on secondary corroboration — do not treat those as fully settled if cited externally.

## SECTION A: Closure-vs-SMT architecture (the most consequential cluster)

A1 — "Typechecker inference algorithms are closure procedures: deterministic, no backtracking, polynomial, because their fragments admit principal solutions." VERDICT: CORRECTED. Unification substep is deterministic + near-linear (Martelli-Montanari; Paterson-Wegman with DAG sharing) and HM has principal types (Damas-Milner) — but full let-polymorphic HM *inference* is EXPTIME-complete worst-case (Kfoury-Tiuryn-Urzyczyn; Mairson), from repeated instantiation of let-bound polymorphic types, NOT from unification or any choice point. "Polynomial" is true of the unification substep, false of full HM inference — the claim conflated them. MLsub/biunification (Dolan & Mycroft POPL 2017) genuinely has closure/saturation structure with principal types. Datalog LFP and abstract-interp fixpoint iteration are accurately closure procedures. The causal link "closure-BECAUSE-principal-solutions" is the orchestrator's synthesis, not a cited unifying thesis. Sources: https://link.springer.com/chapter/10.1007/3-540-52590-4_50 (ML typability DEXPTIME-complete); https://www.seas.upenn.edu/~sweirich/types/archive/1989/msg00092.html; https://popl17.sigplan.org/event/popl-2017-papers-polymorphism-subtyping-and-type-inference-in-mlsub

A2 — "DPLL(T)/CDCL(T) is a boolean search loop around deterministic theory solvers; search lives only in the boolean wrapper." VERDICT: OVERSTATED. Accurate for the EUF+linear-arithmetic core specifically (congruence closure confirmed deterministic near-linear — Nelson-Oppen; Nieuwenhuis & Oliveras 2007, fetched in full). Breaks for other theories: nonlinear arithmetic needs internal branching (sign-splits/CAD), arrays need lemma/instance search, quantifier instantiation (E-matching) searches inside the theory layer. Also simplex is exponential worst-case (Klee-Minty), so "deterministic" ≠ polynomial. Sources: Nieuwenhuis & Oliveras "Fast congruence closure and extensions" Information and Computation 205 (2007). FLAGGED GAP: DPLL(T) (JACM 2006) and Dutertre-de Moura simplex-for-DPLL(T) (CAV 2006) searched but NOT fetched (network timeout) — A2 rests on secondary corroboration for those.

A3 — "Disjunction/boolean structure is THE essential thing forcing search + exponential cost; no disjunction → polynomial." VERDICT: CORRECTED. Disjunction is a SUFFICIENT source (SAT/CNF NP-completeness) but not the ONLY one — HM has zero disjunctive structure and is still EXPTIME-complete (nested let-polymorphism). Corrected form: disjunction is a common source of case-split cost; polymorphic generalization is a documented independent source of superpolynomial cost with no disjunction. Corrects TOGETHER with A1 (same fact undermines both). Sources: same as A1.

A4 — "The architectural difference between a typechecker and an SMT solver reduces largely to how each treats a disjunction (join vs case-split)." VERDICT: OVERSTATED. No source frames it this way; omits independent axes — HM's EXPTIME worst case (unrelated to disjunction), GHC's syntactic-rewriting constraint solving, tsc's structural-subtyping-plus-deliberate-unsoundness, SMT's CDCL(T) on a SAT core. Suggestive analogy, not a demonstrated architectural reduction. Sources: none found addressing this comparison directly.

A5 — subclaims: (a) "HM = first-order unification, near-linear, principal types" CORRECTED (unification substep only; full inference EXPTIME — same as A1). (b) "tsc = local inference + structural subtyping + heavy caching + deliberate unsoundness" CONFIRMED (TS design docs state soundness is explicitly not a goal — https://github.com/microsoft/TypeScript/wiki/TypeScript-Design-Goals). (c) "MLsub = full subtyping-with-inference via biunification on polarized types" CONFIRMED (Dolan & Mycroft POPL 2017). (d) "GHC type-class/family solving = syntactic rewriting not theory reasoning" CONFIRMED (OutsideIn(X) — https://simon.peytonjones.org/outsideinx/).

A6 — "Abstract interpretation handles disjunction by joining in a lattice + widening for termination." VERDICT: NOT VERIFIED — PROVISIONAL. No explicit citation was returned for this claim in the verification pass; the verifier explicitly refused to launder it as confirmed. Must be re-checked against Cousot & Cousot 1977/1992 (join-over-disjunction, widening/narrowing) before treated as settled.

## SECTION B: Disjunction-handling technique taxonomy

B1 — Defer/residuate. CORRECTED. Watched literals (Chaff, DAC 2001) are a propagation-efficiency structure, NOT deferral of a choice — overstated as "residuation." CLP residuation (clpfd) is real but resumption is NOT "at no extra cost" (suspension/wake-up overhead). `-fdefer-type-errors` is the WRONG Haskell example (defers a detected error to a runtime crash, not an unresolved constraint); closer analogue is residual/ambiguous typeclass dictionaries. Sources: https://www.princeton.edu/~chaff/publication/DAC2001v56.pdf; https://www.swi-prolog.org/pldoc/doc/_SWI_/library/clp/clpfd.pl

B2 — Share instead of enumerate (BDDs, egraphs). OVERSTATED. Shared-structure + blowup risk hold, but: BDD size is ordering-sensitive as an intrinsic property (Bryant 1991; multipliers exponential under every ordering) and a BDD is never worse than enumeration itself — "exponentially worse than enumeration" imprecise. Egraph "ordering sensitivity" is largely a naive-impl artifact that egg (POPL 2021) engineers away via rebuilding; egraph cost hinges on rule-set completeness + extraction. MISATTRIBUTION corrected: equality-saturation POPL 2009 authors are Tate, Stepp, Tatlock, Lerner (NOT "Tate, Stepp, Lahiri, Lyons"). Sources: https://www.cs.cmu.edu/~bryant/pubdir/ieeetc86.pdf; https://homes.cs.washington.edu/~ztatlock/pubs/eqsat-tate-popl09.pdf; https://arxiv.org/abs/2004.03082

B3 — Sample/execute. CORRECTED. Concolic/DSE (DART/CUTE/KLEE) and property testing (QuickCheck) accurately incomplete/refutation-oriented. BMC nuance: refutation-only in practice BUT with a computable completeness threshold (Kroening/Ouaknine), absence of counterexample above threshold DOES prove correctness. Sources: https://www.cs.cmu.edu/~emc/15-820A/reading/biere99symbolic.pdf; https://people.mpi-sws.org/~joel/publications/compthresh11.pdf

B4 — CEGAR. CONFIRMED, no correction (Clarke/Grumberg/Jha/Lu/Veith CAV 2000/JACM 2003). Sources: https://dl.acm.org/doi/10.1145/876638.876643

B5 — k-bounded/disjunctive domains. CORRECTED. Disjunctive completion real (Cousot&Cousot; Filé&Ranzato; Bourdoncle 1993); literal bounded-K exists (Sankaranarayanan et al. SAS 2006). But "THE universal tunable dial" overstates — Astrée uses trace-partitioning directives/heuristics, not one scalar k. k=1-is-join/k=∞-is-split describes theoretical extremes, not how real systems expose the knob. Sources: https://software.imdea.org/~mauborgn/publi/esop05.pdf

B6 — Anytime fair enumeration. CORRECTED. "Anytime" (Dean&Boddy 1988; Zilberstein 1996: interruptible, quality non-decreasing) and "fair" (completeness: no branch starved) are SEPARATE independent properties, conflated in the phrase. Sources: http://anytime.cs.umass.edu/shlomo/papers/Zaimag96.pdf

B7 — Residuate to runtime. CONFIRMED (Findler&Felleisen ICFP 2002; Siek&Taha 2006 — type-sound not type-safe, failures become runtime blame). Cost real and can be severe: naive higher-order contracts >100x overhead; nominal redesign (Muehlboeck&Tate OOPSLA 2017) <10%. Sources: https://www2.ccs.neu.edu/racket/pubs/icfp2002-ff.pdf

B8a — "Exact arbitrary disjunction = SAT = NP-complete, hence irreducible exponential; every technique merely redistributes cost." OVERSTATED. Cook-Levin solid, but hardness holds only for GENERAL/unrestricted case — 2-SAT, Horn-SAT, XOR-SAT, bounded-treewidth are POLYNOMIAL. Many real disjunction problems are UNDECIDABLE not merely NP-complete (different barrier). "Cost redistribution" is a defensible informal corollary but NOT a proven theorem — no conservation law exists trading memory/precision/incompleteness/runtime as fungible units. True-in-spirit, not proven. Sources: https://en.wikipedia.org/wiki/Cook%E2%80%93Levin_theorem; https://en.wikipedia.org/wiki/2-satisfiability

B8b — "Industrial SAT works despite NP-completeness because instances are structured." CORRECTED. Backdoors (Williams/Gomes/Selman IJCAI 2003) and community structure (Ansótegui et al. SAT 2012) are real peer-reviewed characterizations — structure EXISTS and correlates with CDCL runtime. But "structure is WHY CDCL works" is causal, stronger than proven (correlation + characterization, not proof VSIDS/clause-learning/restarts provably exploit it). Active unsettled work. Sources: https://link.springer.com/chapter/10.1007/978-3-642-31612-8_31

## SECTION C: Memoization + structural identity

C1 — CDCL clause learning = memoization. CORRECTED. Learned clauses are permanent monotone prunes, but derived by resolution as a GENERALIZED logical consequence pruning a whole class of future branches — apter analogy is "cached generalized lemma/nogood," not literal function-result memoization. Sources: https://en.wikipedia.org/wiki/Conflict-driven_clause_learning (Handbook of Satisfiability chapter could not be fetched — generalization nuance well-attested but not primary-verbatim).

C2 — tsc caches subtype/relation comparisons as a KEY performance mechanism. CORRECTED. Caches confirmed in source (subtypeRelation, assignableRelation etc., Map<string,RelationComparisonResult> keyed on source/target type-id pairs). But no official statement calls it "a key performance mechanism" — superlative is claimant's framing. Existence + structure confirmed; "key mechanism" unsupported; keyed on type-id pairs NOT arbitrary structural content. Sources: https://github.com/microsoft/TypeScript/blob/main/src/compiler/checker.ts

C3 — Infer scales via per-procedure summaries reused across callers + incremental runs; cross-run reuse primary for diff speed. CONFIRMED. Bi-abduction pre/post summary per procedure, reused compositionally within a run; docs explicitly extend to cross-run incremental (only changed procedures + transitive callers re-analyzed). Does NOT conflate compositional vs incremental. Sources: https://fbinfer.com/docs/separation-logic-and-bi-abduction/; https://research.facebook.com/publications/moving-fast-with-software-verification/

C4 — Incremental SAT retains learned clauses across calls + push/pop. CORRECTED. Retention accurate, but mechanism is ASSUMPTION-LITERAL-based (MiniSat solve(assumptions), IPASIR ipasir_assume+solve; auto-clear after solve), NOT push/pop. Push/pop is the SMT idiom (Z3/CVC), not SAT — claim conflated them. Sources: https://github.com/biotomas/ipasir; https://github.com/niklasso/minisat

C5 — Unison: definitions hashed by normalized structure, names as metadata, results cached by hash so renames don't invalidate. CONFIRMED. Hash of AST/ABT with positional refs + dependencies-by-hash (purely structural); names separate; cache "never invalidated"; extends to test-result memoization — CAVEAT: pure/deterministic non-I/O tests only. Sources: https://www.unison-lang.org/docs/the-big-idea/

C6 — rust-analyzer uses salsa, memoizes query results keyed structurally, recomputes only what changed. CORRECTED. salsa memoizes tracked-fn results keyed by fn+args with dependency graph, BUT "recomputes only what changed" oversimplifies — uses revision counter + durability + red-green validation + EARLY CUTOFF/BACKDATING (unchanged output → consumers not further invalidated). Not naive diff-and-skip. Sources: https://rust-analyzer.github.io/blog/2023/07/24/durable-incrementality.html

C7 — GHC interface fingerprints for recompilation avoidance. CONFIRMED, finer-grained than assumed: MD5 fingerprints per interface file AND per declaration; recompile skipped when depended-on fingerprints all match. Sources: https://downloads.haskell.org/ghc/latest/docs/users_guide/separate_compilation.html

C8 — Memoization is amortization not complexity escape; helps only when inputs repeat; stale/mis-invalidated cache = unsoundness bug not just slowness. CONFIRMED. Standard DP pedagogy (no overlap → zero improvement, no worst-case ceiling change). Soundness half backed by real TS wrong-answer cache bugs (#56710 stale cached errors; #30780 missed errors after transitive type change). Sources: https://github.com/microsoft/TypeScript/issues/56710; https://github.com/microsoft/TypeScript/issues/30780

## Net assessment

Nothing fabricated across 3 clusters / ~24 claims, but the recurring failure mode was vague-memory-of-mechanism, and TWO central framings were materially overstated: (1) "typecheckers are polynomial / typechecker-shaped implies fast as a complexity guarantee" — false, full HM inference is EXPTIME-complete worst-case; the speed intuition survives empirically (real code doesn't hit it) but not as a complexity bound. (2) "typecheckers vs SMT = one algorithm family separated by how they treat disjunction" — overstated to the point of not being supportable as stated; a suggestive analogy, holds only for SMT's EUF+LA core. Design consequence for the site-identity / disjunction-policy work: the disjunction-policy framing may still be useful ENGINEERING but must not be justified by the "this is what they really are" architectural claim, which did not survive. Sub-note that HELPS the owner's position: the polynomial FRAGMENTS are real and provable (2-SAT/Horn/XOR/bounded-treewidth), so a "fast floor" defined by membership in a provably-polynomial fragment is on firmer ground than a floor defined by the vague label "typechecker-shaped." Four sources remained unfetched (DPLL(T) JACM 2006; Dutertre-de Moura CAV 2006; Mairson; Cousot&Cousot for A6) — verdicts depending on them are directionally corrected but rest on secondary corroboration; fetch before any external citation.
