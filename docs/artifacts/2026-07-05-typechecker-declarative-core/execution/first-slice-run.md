## The key finding: 100% Open, and why (the predicted H1 wall)

Every single one of the 2174 checked topics across all 8 files came back
**Open**. Zero Proved, zero Refuted. This is not a bug in the harvest or
check-law code (see harvest_test.lua / check_test.lua's 88 passing unit
assertions establishing both work correctly on small fixtures) -- it is the
predicted structural consequence of two facts:

1. **The check law's Proved/Refuted paths require >=2 claims sharing an
   identical topic (site+slot+stratum+modal) from *different* provenances.**
   But `harvest_stated`'s site format is `"<file>:<def_line>:<funcname>"`
   with slots `entry:<param>` / `exit:<n>`, while `harvest_mined`'s site
   format is `"<file>:<line>"` with slots `deref:<name>` / `branch:<which>`.
   These two vocabularies never coincide for the same real-world fact, even
   when a human can see they're "about the same thing" -- e.g. a stated
   param annotation `x: string` and a mined `deref:x` a few lines later
   inside that function are never the same topic, because one carries the
   function name in its site and the other doesn't, and their slot
   namespaces (`entry:`/`exit:` vs `deref:`/`branch:`) never overlap.
   `harvest_axiom`'s claims (site=`"*"`) never coincide with anything
   file-specific either, by construction (see harvest.lua's header --
   instantiating an axiom against a concrete site is itself Hole H1).

2. **This is exactly Hole H1** (open-threads.md): "There is no declarative
   derivation system between the semantics (⊨, undecidable) and solver
   machinery." The check law implemented in this chunk is the strongest
   thing buildable without that layer -- cross-source corroboration -- and
   the corpus run demonstrates concretely that cross-source corroboration
   essentially never fires in practice, because there is no mechanism unifying
   different sources' *site/slot vocabularies* into the same proposition
   space. Building H1 for real would need exactly that unification (e.g. a
   canonical "value at variable x, in scope at line L" addressing scheme
   all three harvesters emit into) -- which is why this finding is framed as
   a substrate gap, not a result deficit, per CLAUDE.md's planning
   discipline.

### 5 concrete "obviously decidable" Open instances (the H1 wall in practice)

Each of these a human resolves in seconds by reading two lines of context,
yet the check law correctly reports Open with a receipt naming the missing
piece -- no hardcoded decision was taken to paper over them:

1. **`lib/lru/init.lua:155 | deref:self | schema=non-nil`** -- inside
   `function Cache:peek(key)` (line 154). `self` is the implicit receiver
   of a colon-call; Lua's calling convention guarantees it is non-nil
   whenever the method is invoked via `:`. Decidable via one fact ("this
   parameter is a colon-call `self`") that the harvester doesn't have
   access to -- it's a fact about calling convention, not about the local
   dereference site itself. This is the missing derivation step: "colon-
   method self is non-nil" is a one-line inference rule H1 would supply.

2. **`lib/json/init.lua:125 | deref:HEX | schema=non-nil`** -- `HEX` is a
   module-level `local HEX = {}` (line 28, populated immediately after via
   a `for` loop) that is never reassigned. Decidable via a
   single-assignment/no-reassignment dataflow fact across the whole file --
   again a fact one step removed from the dereference site, requiring a
   (trivial) def-use derivation the harvester doesn't perform.

3. **`lib/queue/init.lua:157 | deref:FIFO | schema=non-nil`** -- `local
   FIFO = {}` at line 156, dereferenced one line later
   (`FIFO.__index = FIFO`) in the same lexical scope with no intervening
   reassignment. Same missing-derivation-step shape as #2, at even shorter
   range (adjacent line).

4. **`lib/deque/init.lua:62-65 | deref:self`** (four separate Open
   entries, one per line) inside `function Deque:pop_front()` -- same
   colon-call-self argument as #1, repeated across the method body. A
   single "self of a colon-defined method is non-nil" derivation rule
   would resolve all four (and the equivalent instances across every
   other file's methods) at once -- concrete evidence that H1's payoff is
   not per-claim but per-*rule*, closing whole classes of Open findings.

5. **`lib/bigint/init.lua:115 | branch:then | schema=reachable`** --
   an ordinary `if` clause with live, reachable code in both branches
   (not dead-code-eliminated). A human confirms reachability by reading
   the function; the harvester correctly mines the presupposition but the
   check law has no reachability analysis to independently confirm it,
   so it stays Open pending H1's derivation layer, exactly as designed
   (not hardcoded to Proved to make the number look better).

### Refuted verdicts: none observed

Zero Refuted verdicts occurred anywhere in the 2401-claim corpus. Given
finding (1) above (stated/mined/axiom claims never share a topic key in
practice under the current site/slot conventions), this is the expected
consequence of the same structural gap, not evidence that the harvesters

`check_test.lua`'s unit tests (`lib/declc/check_test.lua`) directly exercise
the Refuted path on synthetic same-topic conflicting claims and it fires
correctly there; the corpus run's zero count is a fact about this specific
corpus's harvested claims' site/slot shapes, not about the check law's
ability to detect contradictions when they're actually comparable.
