# Sweep: symbolic execution (breadth family)

Provenance: subagent research sweep, 2026-07-05. Sources are the primary
papers (KLEE OSDI'08, SAGE CACM'12/NDSS'08, DART PLDI'05, SMART POPL'07,
UC-KLEE USENIX Sec'15, Cadar-Sen CACM'13). Read against the certified
formulation in `../declarative-design.md`.

## (a) Witness minting — does SE dissolve "witness ≠ trace"?

Verdict: **yes, by relocating the problem.** SE does not carry traces inside
a proof object at all. The witness is an *input assignment* extracted from an
SMT model of the path condition, and the trace is *reconstructed by replay*:
KLEE "if a path terminates or hits a bug, a test case can be generated by
solving the current path condition for concrete values. Assuming
deterministic code, feeding this concrete input to a raw, unmodified version
of the checked code" reproduces the behavior (KLEE OSDI'08 §1). DART states
it as a theorem: "any error found by DART is guaranteed to be sound" because
errors are only ever reported from concrete executions (DART PLDI'05 §2,
soundness half of the main theorem). So the proof-theoretic open problem the
incorrectness-logic shelf reported (trace-carrying witnesses) is real *inside
the logic*, and simply bypassed by the SE tradition: keep the witness small
(an input), make the trace recomputable (deterministic replay). The design's
"wrong-with-evidence" verdict can adopt this directly: evidence = input/entry
state + replayability, not a serialized trace.

Cost of the dissolution, per the same papers:
- **Replay requires an executable semantics and determinism.** For a static
  checker over Lua this means an evaluator for the fragment the witness
  exercises. Nondeterminism/environment breaks replay (SAGE handles it by
  offline trace capture: "constraint generation in SAGE is completely
  deterministic because it works with an execution trace" — CACM'12).
- **Under-constrained entry states weaken the witness.** UC-KLEE checks
  functions in isolation with unconstrained symbolic inputs; the price is
  false positives from missing preconditions (e.g. BIND: a length field not
  associated with its buffer). Mitigation is *annotations* (data-type
  annotations, INVARIANT macros) used to filter; one annotation filtered 623
  reports (~7.5% of BIND errors); their best checker still had 2.2% FP
  (Ramos-Engler USENIX Sec'15). Mapping: a UC witness is exactly a finding
  whose strength must be discounted by the credence of the *implicit
  entry-state assumptions* — the design's finding-strength product
  (witness-status × credence-of-contradicted) already has the right shape,
  but needs a slot for credence-of-the-witness's-own-assumptions.
- **Compositional SE (SMART, POPL'07) is the documented middle**: test
  functions in isolation, encode results as summaries (input preconditions →
  output postconditions), reuse summaries at call sites. Complexity drops
  from exponential in intraprocedural path bound (DART) to linear (SMART
  main theorem). This is the practical answer to whole-program witness cost.

## (b) Can a refutation chase be budgeted per-claim?

Verdict: **yes — three decades of SE is precisely the evidence that
budgeted, incomplete refutation search is economically viable, provided
verdicts are three-valued.** The economics:

- SAGE's generational search exists *because* symbolic execution of one
  trace is the expensive unit: negate every branch constraint in the path
  constraint so "a single symbolic execution can generate thousands of new
  tests" instead of one (CACM'12). Amortization across claims, not per-claim
  purity.
- Explicit per-claim budgets are standard practice: SAGE's "flip count
  limit establishes the maximum number of times a constraint generated from
  a particular program branch can be flipped"; constraint subsumption and
  unrelated-constraint elimination bound query size (CACM'12). KLEE budgets
  via searcher heuristics + query optimizations: constraint independence +
  counterexample cache cut STP queries to 5% and STP was 92% of runtime
  before optimization (OSDI'08 §3).
- The payoff curve: SAGE found the ANI-parser bug (MS07-017, missed by
  extensive blackbox fuzzing AND static analysis) in 7h36m / 7,706 tests
  from one seed; over Windows 7 development it found ~1/3 of all
  file-fuzzing bugs *while being run last*, i.e. only bugs everything
  cheaper had missed; 300+ machine-years, >1e9 SMT constraints (CACM'12).
- The structural lesson: "in practice, the search is typically incomplete"
  (CACM'12) and DART tracks this honestly with *completeness flags* — when
  the solver falls back to concrete values (nonlinear arith, symbolic
  pointer deref) a flag flips and the tool downgrades its claim from
  "verified" to "searched" (PLDI'05 §2). That flag IS the design's
  `undecided` verdict, independently invented. The never-reject law matches
  SE exactly: exhausted budget ⇒ undecided, never ⇒ reject.
- Frame-relevant caveat: SE's economics work because cheap methods run
  FIRST ("use both… blackbox is a good start; once the low-hanging bugs are
  gone, fuzzing has to become smarter" — CACM'12). A per-claim chase should
  be tiered: cheap consistency checks before SMT-grade refutation.

## (c) Environment / FFI boundary

Verdict: **known worst problem; two strategies with well-measured costs,
and the design should expect to need both.**

1. **Models** (KLEE): redirect boundary calls to hand-written models that
   generate constraints. Cost: ~2,500 LOC for ~40 syscalls, and the models
   are "crude" (single directory, N symbolic files); modeling at the
   *narrowest* interface (syscalls, not libc) is the key economy — compile
   uClibc through the checker rather than model fread/fopen (OSDI'08 §4).
   Lua analog: model the C API surface / stdlib intrinsics, and run pure-Lua
   library code through the checker itself rather than modeling it. This is
   exactly crescent's existing `--:: declare` stdlib posture.
2. **Concretization** (DART/concolic): at an external call or undecidable
   expression, substitute the concrete value and flip a completeness flag
   (PLDI'05). Under-approximate: no false alarms, guaranteed-real witnesses,
   but incompleteness is explicit. Lua analog: an FFI return becomes an
   `unknown`-grade pool entry; any finding that depends on it inherits
   degraded witness-status rather than being suppressed or trusted.
3. UC-KLEE's third way — leave the boundary *unconstrained* and let
   annotations claw back precision — is the closest match to the design's
   graded-assumption pool: FFI facts enter as low-credence mined beliefs,
   annotations raise credence, and false positives are the measurable price
   of missing annotations (USENIX Sec'15 numbers above).

Papers' consensus (Cadar-Sen CACM'13): environment interaction is a
first-class challenge alongside path explosion and constraint solving; every
successful tool mixes concrete/symbolic execution rather than modeling
everything.

## (d) Pool-shaped structures — mutual consistency of path conditions?

Verdict: **no mainstream SE system checks path conditions for MUTUAL
consistency — and structurally none could**, because distinct path
conditions are mutually exclusive *by construction* (they differ in at least
one negated branch constraint). Per-path satisfiability is the only
consistency question SE asks. The design's pool is therefore NOT
"a set of path conditions"; the analogy fails at exactly this point.

Two nearby structures are pool-shaped, though:
- **Compositional summaries are a pool of reusable assumptions.** SMART's
  summaries (pre/post pairs) are minted once and reused as *hypotheses* when
  testing callers (POPL'07). Follow-up work ("Statically Validating Must
  Summaries for Incremental Compositional Dynamic Test Generation",
  Godefroid-Lahiri-Rubio-González, VMCAI/HVC 2011 line) re-validates
  summaries when code changes — a summary used as hypothesis must be
  re-checked as obligation against the new code. This is the
  hypothesis-survives-as-obligation law, independently arrived at, with an
  incremental-revalidation twist the design doesn't yet have (H-open:
  what invalidates a pool entry when the program changes?).
- **UC-KLEE's annotation/filter loop is credence grading in the wild**:
  reports contradicting a user INVARIANT are flagged and filtered — i.e.
  finding strength is computed against the annotation's (assumed-high)
  credence, exactly the product order.

## Frame threats, ranked

1. **(d) is a partial frame-breaker**: "collected path conditions ARE
   assumption pools" is wrong as stated; the pool-shaped thing in SE is the
   *summary store*, not the path-condition set. If the design leans on SE
   for its consistency-checking layer it inherits per-claim satisfiability,
   not mutual consistency — the mutual-consistency layer must come from the
   Dialyzer genus, with SE supplying only the witness-minting substrate.
2. **Replay-based witnesses require an executable semantics** for the
   witnessed fragment. Cheap for pure Lua; at the C boundary the witness
   degrades to "input + assumptions", i.e. witness-status is itself graded
   — the design's binary-looking witness-status should be a scale.
3. **Budget economics favor tiering**, not uniform per-claim chases:
   cheapest checks first, SMT-grade refutation last, amortize one expensive
   analysis across many candidate findings (generational search).
